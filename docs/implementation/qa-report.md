- Date: 2026-10-29
- Base: branch `integration` (all modules, workflows, dashboard and docs merged)
- Scope: end-to-end tests, review of the code against ADR 0001 to 0009, security review, defect list. Nothing outside `test/e2e/**`, `test/fixtures/e2e-qa/**` and this file was changed.

## 0. Summary

- The collector, the git writer, the keepalive, the site builder and the analysis tool work together as designed. 59 new end-to-end tests (10 files in `test/e2e/`) run `runCollect` and `runCli` against a local bare `data` remote with a depth-1 clone (the shape of `actions/checkout` with `fetch-depth: 1`), a depth-1 clone of `main`, a second writer and a fake `HttpClient` that serves the response shapes of all four sources for the ten real coins of `config/coins.json`.
- The case that the module tests did not cover works: after a rejected push, `fetch` and `reset --hard` in a shallow clone give the remote tip, the write is redone, and no row is lost or doubled (tests in `conflicts.test.ts`).
- No data-loss or data-corruption defect was found in the normal paths. 13 defects and gaps were listed in section 4. None was high. Four were medium: D-01 (restart counts as a failed run), D-03 (a committed half line blocks every later run), D-04 (the all-sources-down case is silent during the 14-day test) and D-06 (a real 50% move is rejected for good in production).
- Update after the fixes on `integration`: D-01, D-02, D-03, D-04 and D-06 are fixed (commits in section 4) and re-tested here. D-05 (`.gitignore`) is not on `integration` yet, so it stays open. The seven others (D-07 to D-13) are open. The tests that pinned the old behaviour (three `todo` tests and four `characterisation` tests) are replaced by normal tests of the new behaviour. No `todo` test is left.
- The one allowed dry-run smoke test against the real sources succeeded (section 5).

### 2.2 Pins, runner, tools

- Every `uses:` line in the six workflows is a 40-hex SHA with a `# vX.Y.Z` comment. Owners: `actions`, `github`, `ossf` (one third-party action, Scorecard). Whether the SHAs match the tags was not checked (no GitHub access); `zizmor` online audits and Dependabot do that in CI.
- `ubuntu-26.04` everywhere, no `ubuntu-latest`. `collect` and `publish` check the Node major.
- Tools in CI are pinned by version (`check-jsonschema`, `zizmor`) or by version and SHA-256 (`actionlint`). They are installed in a venv under `RUNNER_TEMP`. `npm ci --ignore-scripts` is used in every job.
- Not run here: `actionlint`, `zizmor`, `check-jsonschema` (not installed, not installed by me). UNVERIFIED until the first CI run. `zizmor` may flag `persist-credentials: true` (rule `artipacked`) in `collect.yml`; this is intended (ADR 0009 open question 5).

### 2.3 Secrets and logs

- No repository secret exists or is used. `GITHUB_TOKEN` is read in one place (`createGitHubIssueClient`) and sent only in the `Authorization` header to `GITHUB_API_URL`. That URL must be https, or `http` on `127.0.0.1` or `localhost` (test servers). After the D-04 fix the CLI builds this client in both phases whenever `GITHUB_TOKEN` is set. It calls the API only for an alert, an open Issue or a failure streak of 4 or more; a healthy run makes no call (tested).
- A test runs the real CLI with a fake token in the environment and checks that the token is not in the log, in the status file or in any commit message.
- The collector logs: one line per source (status code, ms, counts, error code), one line per rejected coin (coin id and a stable reason code), `skipped <coin> <src>: <reason>`, the push result, and `describeError` of an exception (first line, 200 characters). Source response bodies are never logged. The HTTP client keeps no body on failure. Git errors print the first stderr line (a remote URL without a token, because checkout stores the token in a header, not in the URL; UNVERIFIED on a real runner).
- Alert text uses only numbers from validated rows, coin ids and names from the config, and constants (`src/alerts/templates.ts`).

### 2.5 Content Security Policy of the page

`<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none'">`. The page has no inline script, no inline style, no style attribute and no event handler attribute (tested). The vendored uPlot sets styles through `element.style` only (no `cssText`, no `setAttribute("style")`, no `<style>` element, no `innerHTML`), so the policy does not break it. A real browser run of the built page (served from localhost) showed the chart, the alert row and no console error.
